# 验证与 Studio 部署实现范围

目标：把已有验收与 Studio 运维变为可重复执行的仓库命令，保留原 4391 服务和用户聊天记录。

1. 增加统一验证入口：本地测试、独立 Studio Agent API、隔离任务 API。默认不触发付费调用；显式选择 DeepSeek。统一报告中区分 API 和页面验收，不伪造浏览器证据。
2. 增加独立 Studio 镜像与部署控制器：不可变源码版本、Linux 锁文件安装、独立数据、SQLite backup、运行排空、单实例切换和失败回退。状态命令同时显示期望和实际版本，不使用原任务部署脚本。
3. 本地回归及控制器错误场景测试后，在 tencent-server 验证构建、聊天保留、真实模型、页面回复、回退及正式任务数据未变化。真实场景有限执行，修复失败原因后再重试。

完成标准：命令及前置条件有文档，失败返回非零且留下必要报告；新 Studio 自带全部运行依赖；成功切换和回退不会丢弃当前聊天；临时服务停止；真实 API 与 UI 证据对应待交付源码。

范围外：CI 服务接入、新 Agent 业务、正式用户认证、真实手机及通知、客户端渲染、任务服务升级。首次接管旧 Studio 如不具备排空接口，必须显式识别为旧实例并采取受控维护切换，不能宣称其支持无损排空。

2026-10-23 已完成上述范围，命令见 [operations.md](operations.md)，真实 API、页面、备份和回退证据见 [operations-validation.md](operations-validation.md)。具体失败和限制按验收记录保留。
