# Mastra 设备工具实验记录

日期：2026-10-21（北京时间）。

目标是在不使用模型 key 的情况下，验证 Mastra 实际工具循环和持久暂停是否能支撑云端决策、设备执行、结果回传及继续决策。

## 本地结果

`npm.cmd test` 通过。共 7 个子场景（测试运行器加外层父测试共计 8 项）：

1. 手机电量 82 后继续查询日历，模型结果包含只有设备返回的会议标记。
2. 手机电量 12 后结束，不查询日历。
3. 拍照工具暂停后替换服务进程，回传结果后继续；相同回传去重，冲突回传拒绝。
4. 电量已完成、日历暂停时停止服务；结果先写入设备账本，再启动新进程，自动恢复正确的日历调用。
5. 取消结果跨重启保留，迟到设备结果返回 410。
6. 设备超时转失败；没有 key 的 DeepSeek 请求返回 412。
7. 非法电量被拒绝；权限拒绝作为工具失败返回，不当作空数据。

## 服务器结果

已在 `tencent-server` 的 `/home/ubuntu/xagent-mastra-lab` 部署独立容器，2026-10-21 17:03（北京时间）验收通过。原始结构化结果保存在 [server-verification.json](server-verification.json)。

7 项检查均通过：两个设备工具及结果驱动后续执行、低电量分支、真实容器重启后恢复暂停的拍照调用、重复结果去重与冲突拒绝、取消后拒绝迟到结果、设备超时终止、未配置 DeepSeek key 时明确拒绝真实请求。

本轮没有调用 DeepSeek。服务仅映射服务器 `127.0.0.1:4391`，模型凭据位于服务器项目内未提交的 `.env`，初始 key 为空。

## 真实 DeepSeek 验收（2026-10-22）

09:39（北京时间）在同一台服务器完成，模型 `deepseek-flash`，供应商域名 `api.deepseek.com`，Node v24.22.0。运行配置从已有 `.env` 加载；测试没有读取或输出密钥。

4 个真实模型场景、5 项检查全部通过，总计约 11.7 秒：

| 场景 | 结果 | 单场景耗时 |
| --- | --- | --- |
| 电量 82 后查询日历 | 顺序调用 readBattery、queryCalendar，回复引用工具实际返回的随机日程标记与电量 | 3.163 秒 |
| 电量 12 的分支 | 建议充电，未查询日历 | 2.026 秒 |
| 请求拍照后重启容器 | 恢复原暂停运行，回传后回复引用随机照片回执 | 4.124 秒（包含容器重启） |
| 拍照结果重复与冲突提交 | 相同结果返回重复收据，冲突返回 409，没有再次恢复模型运行 | 并入拍照场景 |
| 电量读取权限被拒绝 | 明确说明无法读取，没有继续查询日历或猜测电量 | 2.320 秒 |

原始回复及事件见 [deepseek-verification.json](deepseek-verification.json)，可复现脚本为 `scripts/verify-deepseek.py`。测试使用合成手机数据和明确的工具策略，证明真实模型与 Mastra 的端到端链路；没有验证真实手机、开放目标规划质量、长期稳定性或并发负载。这些耗时是小样本观察，不是服务 SLA。

## 初步判断

Mastra 的工具暂停和持久恢复可作为设备异步工具链路的基础。设备作业、回调记录、取消与去重仍由应用层负责。

脚本模式与真实模型模式均已验证。DeepSeek 能在给定测试策略下选择工具、消费返回值并在持久暂停恢复后继续；真实手机、更多工具和更开放的决策场景仍待后续接入。
